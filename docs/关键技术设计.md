### 一、RAG 图文精准定位

这部分想做的其实是让AI回答的内容后面有个连接符号，然后你点击符号跳转到对应的PPT的页面，并高亮文字。

具体的流程基本就是两个词，不过文档里写得高档点，一个是“语义锚点”，说的是传入PPT后，利用OCR和插件解析出，文字内容+坐标（相对坐标，要归一化），然后以向量化的形式存到数据库里。还有个词是“双路召回”，就是AI利用数据库进行搜索时，系统同时用“语义向量相似度”和“关键词精准匹配（BM25）”去数据库查找然后综合排序，说人话就是用pgvector 的余弦相似度找最相似的 Top-K，然后用BM25词频统计算法和相关插件，计算提问中关键词在出现的频率和权重，取 Top-K，两边Top-K用RRF 算法得到最终候选集。最后再将最后的候选集喂给，让AI给出答案以及引用连接的符号。

###### 具体的技术选型和插件选择暂定如下，到时候可能因具体部署发生更改：

- 版式解析与 OCR：`MinerU` (PDF-Extract-Kit) 
  - 不仅能做 OCR 识别文字，还能精准识别出哪里是“段落”、哪里是“标题”、哪里是“公式”，并直接返回每个模块在原图上的物理坐标（Bounding Box）。
- 数据库与双路召回插件：
  - 核心库： PostgreSQL。
  - 向量插件：`pgvector`（用于存储大模型生成的 Embedding 向量，执行余弦相似度检索）。
  - 分词插件： `pg_jieba`（集成在 PostgreSQL 中，专门用于对中文提问进行分词，配合数据库自带的全文检索 FTS 实现 BM25 词频计算）。
- 大模型基座：
  - Embedding 模型： 阿里 `bge-m3`（多语言、高性能，适合生成向量）。
  - 重排序模型： `bge-reranker-v2-m3`（用于融合后对候选集进行最后一次精准打分）。

###### 具体流转步骤设计：

- 解析与坐标归一化入库
  - 系统接收 PDF，调用 `MinerU` 切分出逻辑段落。
  - 获取段落的绝对坐标 `[x0, y0, x1, y1]`，将其除以当前页面的宽和高，转化为 `0~1` 之间的归一化相对坐标。
  - 将文本转化为向量，连同归一化坐标、所在页码一起存入 PostgreSQL。
- 混合双路召回与融合 (RRF)
  - 学生提问后，系统并发执行两路查询：一路用 `pgvector` 找语义最相近的切片，一路用 `pg_jieba` 分词找包含关键术语的切片。
  - 利用 RRF (倒数排名融合算法) 将两份结果合并。再通过 Reranker 模型提取出最终的 Top-3“黄金上下文”。
- 前端溯源与跨端高亮
  - 大模型依据上下文生成答案，并输出带有坐标参数的 JSON 引用标签。
  - 前端选型： Flutter 端使用 `syncfusion_flutter_pdfviewer` 插件。
  - 前端接收到相对坐标后，乘以当前设备屏幕上 PDF 视图的实际宽高，逆向算出像素位置，通过 `CustomPaint` 在该位置叠加一个半透明黄色高亮遮罩，并通过控制器自动滚动至该页。

### 二、DSL 动态渲染

这部分要做的是生成动画，具体实现思路是这样，前端提前写好几个基础的可视化组件，如方块、箭头等。然后设计一套DSL指令（其实就是JSON脚本，设计好格式），去更新这几个组件的状态，然后flutter底层的图形渲染引擎自动补齐中间的动画过渡帧，形成动画。需要生成动画时，让AI学习好指令格式，然后它生成对应的指令即可。

###### 前端基础微组件库设计

- DataNode（数据节点）：代表数组元素、树节点。
  - *属性：* `id` (唯一标识)、`value` (数值)、`index` (当前逻辑位置)、`color_status` (颜色：默认/高亮/完成)。
- Pointer（逻辑游标）： 代表算法中的指针（如 i, j, left, right）。
  - *属性：* `id`、`label` (显示的字母)、`target_id` (当前指向的数据节点 ID，改变这个属性，箭头会自动飞过去)。
- Edge（连线组件）： 用于展示树或图的关系。
  - *属性：* `source_id` (起点节点)、`target_id` (终点节点)。
- StatePanel（状态控制台）： 显示当前执行的伪代码行号或局部变量状态（如 `dp[i] = 5`）。

###### DSL指令设计

```json
{
  "version": "1.0.0",           // 协议版本号，方便后续升级向下兼容
  "frame_id": 1024,             // 唯一帧编号，用于前端快照缓存和拖拽回溯
  "timestamp": 1698001234,      // 生成时间戳
  "narration": "因为 8 大于 5，所以交换两者的位置...", // AI 同步输出的讲解文本
  "global_config": {
    "duration_ms": 600,         // 全局默认动画执行时长（毫秒）
    "auto_play": true           // 是否接收到立刻自动播放
  },
  "actions": [                  // 核心数组：本帧内需要同时执行的所有原子指令
    // ... 具体指令对象
  ]
}
```

1. 创建/初始化指令 (`CREATE`)：在画布上生成一个新的组件。通常在算法演示的第一步大量使用。

```json
{
  "action": "CREATE",
  "entity_id": "node_0",          // 全局唯一标识符
  "entity_type": "DataNode",      // 见上面的组件字典
  "properties": {
    "value": "8",
    "logical_index": [0, 0],      // 逻辑坐标：一维数组可用 [0]，矩阵可用 [0, 0]
    "theme": "default"
  }
}
```

2. 更新状态指令 (`UPDATE`)：改变画布上已有组件的值、颜色，或者让指针改变指向。

```json
{
  "action": "UPDATE",
  "entity_id": "pointer_i",       // 要操作的组件 ID
  "properties": {
    "target_id": "node_1",        // 告诉指针去指向新的节点（前端会自动计算移动轨迹并平滑滑过去）
    "theme": "active"             // 颜色变为激活态（变成橙色）
  }
}
```

3. 交换指令 (`SWAP`)：针对排序算法设计的专用复合指令。本质上是同时交换两个 `DataNode` 的 `logical_index`。

```json
{
  "action": "SWAP",
  "entity_id_1": "node_0",
  "entity_id_2": "node_1"
  // 约束：前端收到后，将两个节点的逻辑位置互换，并利用 Flutter AnimatedPositioned 触发交叉移动动画
}
```

4. 建立连接指令 (`LINK`)：专用于生成二叉树、链表、图等数据结构的边。

```json
{
  "action": "LINK",
  "entity_id": "edge_0_1",        // 这条边本身的 ID
  "entity_type": "Edge",
  "properties": {
    "source_id": "node_0",        // 从 node_0 出发
    "target_id": "node_1",        // 指向 node_1
    "style": "solid"
  }
}
```

5. 销毁指令 (`REMOVE`)：从画布上移除变量或节点（如链表节点删除、局部变量作用域结束）。

```json
{
  "action": "REMOVE",
  "entity_id": "pointer_j"        // 指定 ID 即可，前端收到后触发渐隐（FadeOut）动画
}
```

###### 具体步骤设计：

- AI 编译： 大模型根据算法逻辑，生成如上所示的 JSON 格式指令流。

- 指令分发： 移动端收到指令，解析出 `frame_id` 和 `actions` 动作列表。

- 状态突变与插值：前端直接修改对应组件的底层状态。利用 Flutter 外层包裹的 `AnimatedPositioned` 和 `AnimatedContainer`插件，状态的突变会被框架自动转化为持续 500ms 的平滑位移和颜色渐变动画，无需逐帧重绘代码。
