## python
Python的环境配置是直接通过requirements.txt文件进行的，通过Dockerfile将requirements放进docker里面构建镜像来保证运行。在正常的开发过程中可以直接在本地测试好后再导入requiements.txt文件。
可能存在的问题是镜像中的python的源与本地源不一致导致出现版本问题。但是在Dockerfile中显式子定义了pip的源地址，一般不会出现问题。

## Java

### 1. 插件问题
项目基于 Java 17+ 和 Maven 构建。在 VS Code 中开发建议安装 `Extension Pack for Java` 和 `Spring Boot Extension Pack` 插件。

### 2.vscode显示Bug
如果直接在项目根目录下打开Java，由于Vscode的插件限制会出现很多的依赖路径错误，只要单独在Java文件夹下打开Vscode这些错误就都会消失。

### 3.Mvn版本问题
由于开发的环境和Docker中的依赖环境不一致，可能会出现下载的时候出现大量报错。Vscode的Spring Boot插件提供了一种解决方案，就是创建的时候会自动生成两个脚本在项目文件夹下，其作用就是可以在你没有下载Mvn的情况下使用脚本内置的Mvn版本进行编译和运行，从而避免版本不一致的问题。
本地测试的时候直接使用`./mvnw install`就可以下载依赖。
